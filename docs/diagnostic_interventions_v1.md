# 参数干预诊断 v1（开发实验，不是 v0.2 正式结果）

本方案在新开发物理运行前写定。原 v0.1 代码、任务、评分、初值、模型输出、测试条件和结果均保留，不按诊断结果重选 donor 或重报原测试收益。

## 依据与待检验解释

旧 pilot 的两个接受产物分别来自 Robotiq 随机搜索 seed 0 与 Kimi seed 0。选择这两个 run 是为了事后解释已经观察到的结果，存在明确的选择条件，不代表所有 donor。

Kimi 目标预算 0/5/20 的最终技能均未改变；预算 5 的两侧选择原参数，预算 20 的候选在验证后回滚。预算 0 的五次目标失败都已抬升约 0.119 m 并进入 HOLD，但稳定保持时间为零。在高于初始物体中心 0.08 m 的全部记录采样中，角速度始终高于 0.5 rad/s。各失败回合的该阶段角速度中位数约 0.544–0.599 rad/s。

这支持“角速度条件阻止计时”的评分解释，不能仅凭旧轨迹断言某参数导致了旋转，更不能归因于已认证的具体接触拓扑。新实验检验：

- 全套 Kimi 参数在独立开发条件上是否仍表现出本体相关的旋转/稳定性差异。
- 抓取高度、预抓取净空、闭夹等待、抬升加速度中的单项改动，在初值与 Kimi 两个参考配置下分别有什么影响。
- 单项效应是否依赖其他参数；若依赖，应报告交互，不能将所有损失归给某一字段。
- 相同初值的两次独立真实执行是否有差异，以检查零差对照和仿真重复性。

## 固定设计

- 生成器保持冻结物理分布，`dev` 条件种子 `2026102501`，预先生成 6 个条件；在两个本体与所有配置间配对。
- 对原 pilot 全部 train/validation/audit/test 条件检查 condition ID、reset seed 与物理条件指纹无重合。新条件不能选择性替换，不复跑原正式测试条件。
- 12 个配置：Initial、完整 Kimi 源产物、完整 Random 源产物；从 Initial 分别改成 Kimi 的四个变化字段；从 Kimi 分别恢复这四个字段；Initial 的另一次真实执行。Kimi 的最大抬升速度与 Initial 一致，不人为制造第五个变化字段。
- 两个本体 × 6 条件 × 12 配置 = **144 个有效物理回合**，不做任何别名，也不调用 LLM。每个条件内的配置顺序按预声明规则轮换，无结果驱动的顺序调整。
- 使用原冻结执行器、适配器、场景、评分阈值和每回合独立新环境。诊断候选是人工规定的干预，不是学习得到的新能力。
- 每个无效调用最多立即重试一次，每本体最多两次基础设施重试；全部实际尝试保留，超过限制停止，不能把未完成条件算失败或零收益。

## 指标、边界与复现

主要描述量为同条件配对成功数与差值、获得/丢失成功的条件数。辅助指标为最大抬升、实际连续保持、终止原因、阶段时长、抬升参考速度和实际 TCP 速度/跟踪误差，以及高于抬升阈值后的角速度超限采样比例。采样点不作为独立学习重复；线速度与角速度阻断可能重叠，不能相加解释全部失败。

比较包括完整产物对 Initial、单项改动对对应参考配置，以及 Initial_repeat 对 Initial。6 个条件仅构成探索性机理检查，不作总体显著性或正式迁移收益主张。旋转现象也可能包含仿真数值效应；须保留零差对照、真实跟踪与固定依赖信息。

`tools/diagnose_transfer.py plan` 写出不可变方案与 SHA，绑定原 source checkpoint、完整旧执行输入和诊断工具。`run` 在两个指定 GPU 上运行并在结束后核对 journal、实际调用、case、轨迹和成本；生成的所有报告保持 `formal_result_eligible=false`。磁盘低于原 2 GiB 守卫或存在不确定的在途调用时不自动重跑。

```bash
.venv312/bin/python tools/diagnose_pilot_history.py \
  --suite runs/complete-v2-20261023/pilot --output runs/history-review-NEW.json
.venv312/bin/python tools/diagnose_transfer.py plan --study runs/interventions-NEW
ACCEPT_EULA=Y .venv312/bin/python tools/diagnose_transfer.py run \
  --study runs/interventions-NEW --gpus 0 1
```

开始 GPU 执行前提交工具与设计，并归档实际生成的 plan。原始轨迹、调用 journal 和全部真实成本存本机独立运行目录；只发布不含原测试条件的摘要。停止后的续跑须先核对监督器及在途调用，使用相同 plan 的单本体 `worker` 命令，不重建方案。
