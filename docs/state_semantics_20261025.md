# 原生速度语义核查：2026-10-25

## 已确认的证据与解释边界

旧 pilot 的 Kimi Robotiq→Panda seed 0 在预算 0 上有五次失败。它们均已抬升约 0.119 m，但记录的原生角速度一直超过冻结的 0.5 rad/s 阈值，保持计时为零。目标预算 5 未发生有效参数变化；预算 20 的验证中，原参数与候选均 4/4 成功，中位时间 7.78→7.68 秒，约 1.3% 改善未达到 5% 门槛，故回滚。不能据此调低门槛后重报结果。

交叉检查旧轨迹发现，原生角速度与姿态差分的变化率差异很大。因此，**“原生角速度门槛阻断了成功”有证据，“物体确实在持续宏观旋转、物理技能已经退化”尚无充分证据**。旧报告中的负迁移首先应解释为当前冻结成功判据上的负差值。

为区分读取错误、单位错误和约束求解语义，完成了两个独立原生探针，均不修改生产源代码或上游：

| 探针 | 实测 |
|---|---|
| Panda、首个预声明开发条件、完整 Kimi 参数；200 Hz 直接读取 PhysX 并与 Arena API 对照 | 1,704 个物理采样、853 次控制状态读取；API 与原始线/角速度的最大差均为 0；该回合成功 |
| 同一接触回合末尾 0.5 秒，事后固定窗口描述 | 原生角速度范数中位数约 0.32849 rad/s；相邻姿态推算约 0.001185 rad/s；原生 z 角速度积分约 −0.16405 rad，姿态推算 z 转角累计约 −0.0000256 rad |
| 自由飞行校准，注入 z 角速度 0.2 rad/s，20 个 5 ms 步长 | 原始角速度中位数约 0.19950 rad/s；姿态推算约 0.19655 rad/s；API/原始差为 0；物体最低中心高度 0.35091 m，无桌面接触 |

这两次探针未发现简单的 API 读取或度/弧度换算错误，但不构成对所有状态路径的完整认证。

PhysX 官方文档说明：有接触或关节约束时，报告速度通常不能要求与两步之间的位置变化率一致；求解器分别处理位置与速度误差，积分姿态与对外报告的速度涉及不同阶段。它为本次差异提供了合理解释，**尚未证明本场景差异完全由某一求解器选项造成**。见 [PhysX Solver Iterations](https://nvidia-omniverse.github.io/PhysX/physx/5.8.0/docs/Simulation.html#solver-iterations)。

原冻结审计依然证明版本、执行身份、配对和账本一致；它没有验证这一物理测量语义。不能把 `formal_result_eligible=true` 扩大解释为物理真实性或通用技能收益已经认证。v0.1 历史结果、评分和配置完整保留，不事后将原生速度替换为姿态差分来改判成功。
