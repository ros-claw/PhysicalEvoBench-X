# 物理步长与求解器敏感性 v3

本设计在本批原生执行前提交。不改候选判据、原 task 或 learner，不重新评分旧 pilot；所有新结果 `formal_result_eligible=false`。原生工具显式版本化，保留 v1 整批失败和 v2 匹配诊断。

| 配置 | 物理 dt | decimation | 位置迭代 | 速度迭代 |
|---|---:|---:|---:|---:|
| baseline | 5 ms | 4 | 64 | 4 |
| half_physics_step | 2.5 ms | 8 | 64 | 4 |
| double_position_iterations | 5 ms | 4 | 128 | 4 |
| double_velocity_iterations | 5 ms | 4 | 64 | 8 |

每个非基线配置只改变一个物理因素。物理步长变化时 decimation 同步调整以保持 50 Hz 控制。物理轨迹观察固定 200 Hz：2.5 ms 步长仅每两步读取一次，不能将变密的观测误称为 dt 敏感性。50 Hz 与 200 Hz 仍按候选 v1 的同一 0.1 秒路径窗口评分。

每配置、每本体先进行两个控制步的配置探针，读取动态刚体及 articulation root 的实时 USD PhysX 求解器属性和场景迭代上下限，并核对实际物理步数/控制周期。它们是 8 次真实配置调用，**没有任务成功成绩**。读回仅认证场景中的设置，不宣称测到了求解器实际执行的工作量。探针不通过则该 worker 不继续完整任务。

完整任务为 36 次独立场景：两本体的名义保持、20 N 单控制周期上抛、抬升后释放、8 mm/4 Hz 持续晃动，另加 Robotiq 选定开发分歧条件，均横跨四个配置。每回合准备 0.5 秒、任务观察 15 秒，准备动作统一使用原 runner 的零相对动作。配置顺序按场景轮转，全部顺序先写入 plan。没有别名、模型调用或自动重试。

接受检查：实时配置与请求一致；候选 50/200 Hz 分类一致，成功完成时间差不超过 25 ms；名义/开发分歧病例候选成功，三个负对照候选失败；反例必须实际离桌并达到原预声明的释放/运动刺激条件。刺激未生效属于验证未通过，不能充当正确拒绝证据。所有完整任务须保留完整时段或实测硬约束终止证据。旧原生速度判据只作描述性记录，不要求其在改变物理配置后保持某个分类。

改变物理配置本身可能改变抓持轨迹、滑落或晃动幅度。报告必须将“实际物理行为改变”“同轨迹两观测频率分歧”“刺激未生效”分开，不将所有结果变化归咎于判据。此批仅有固定控制和一个事后选定的开发病例，没有新学习、总体效果估计或独立安装声明。

调用共 44 次（8 配置探针 + 36 完整任务）。全部调用、失败、未决状态和已知成本保留 journal；源码/配置/hash 与计划在 GPU 前提交。无论整体通过与否都保留完整矩阵，不按结果修改阈值、丢弃配置或选换 seed。只有结果和轨迹核对完成后才决定后续版本。

## 公开输入复现

已归档选定的**开发**病例小型 JSON 和原计划/报告，不含私有正式测试条件或大型轨迹。全新 checkout 可先生成明确标记的衍生输入，再用未修改的 v3 工具创建新的物理计划：

```bash
PYTHONPATH="$PWD/src" python tools/prepare_public_physics_inputs.py --output "$PWD/runs/public-source-inputs"
PYTHONPATH="$PWD/src" python tools/validate_pose_physics_v3.py plan --study "$PWD/runs/new-physics-study" --source-study "$PWD/runs/public-source-inputs"
# 然后检查、保存新 plan，使用自己已安装的原生解释器执行新 study。
```

衍生输入只修改源证据的路径映射并重算 manifest hash，原物理报告逐字保留并明确属于原机器。该准备步骤没有执行物理调用；它不认证一次新的成功，不要求访问原机器的 `runs/`。工具拒绝覆盖已有匹配诊断目录。新的原生执行仍须拥有固定依赖、资产和许可，并保留全部调用。

## 实际执行结果

44/44 次原生调用完成：8/8 配置探针、32/32 预定正反例、4/4 选定开发病例均符合预声明验证标准，没有基础设施失败或未决物理调用。观察到的仿真时长合计 558.32 秒，累计回合墙钟 4,913.50 秒；后者包含并发和共享 GPU 环境下的实际成本，不用作受控吞吐比较。8 个配置探针没有任务成功成绩，负对照被正确拒绝不等于 learner 任务成功。

候选的 50/200 Hz 分类在全部完整任务上一致。选定 Robotiq 病例在四种配置下均于 7.480/7.465 秒达到候选成功；旧判据在 baseline 与加倍位置迭代时超时，在减半物理步长与加倍速度迭代时成功。它是一个事后选定条件的敏感性证据，不估计总体频率，也不把改变物理参数产生的全部差异归咎于判据。

新工具 baseline 的 775 步时间、原生动作、TCP 和物体位置四组数组与原开发病例逐项完全相同；除 episode ID 外，全部公开观测字段也逐项相同。因此该病例上的测量分歧没有靠改变基线控制或读回数据产生。跨其他物理配置并不要求轨迹逐项相同。

收尾审计第一次在写 JSON 时遇到 NumPy 布尔类型错误，日志与失败状态保留；修正输出类型后仅重跑离线核对，没有重跑物理实验、修改阈值或删除记录。完整矩阵、留存状态重算、每配置曲线和限制集中在 [实际证据](../evidence/measurement/physics_sensitivity_v3/report.zh-CN.md)。

公开输入还在一个干净工作树生成了新计划；全部 44 个任务、技能、物理配置和测量设置与原计划相同，见 [公开计划核对](../evidence/measurement/physics_sensitivity_v3/public_input_plan_review.json)。这是数据/计划检查，没有新增物理调用。

通过范围仍有限：固定几何控制和一个选定开发病例；观察频率固定 200 Hz，2.5 ms 物理步长的中间状态没有全部采样。不认证任意物体、接触方式、机器或更高频运动。候选未升为默认 judge，也没有冻结新的正式任务；v0.1 旧结果保持原定义，未证明正迁移。
