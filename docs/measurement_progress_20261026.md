## 候选判据与开发重放

已实现显式加载 YAML 的姿态路径窗口候选、完整时长双判据观察器和原生对照工具。CPU 与共享原生 Python 环境各通过 110 项 CPU 测试；该事实不等于物理验证通过。

完整重放固定的 144 条开发轨迹，验证源计划与记录哈希，结果如下：

| 本体 | 观察到候选成功 | 记录结束时尚无候选结论 | 观察到候选失败 |
|---|---:|---:|---:|
| Panda | 0 | 72 | 0 |
| Robotiq | 65 | 7 | 0 |
| 合计 | 65 | 79 | 0 |

这些是可观测结果计数，不能除以 144 当作候选成功率。旧判据成功后会结束记录，79 条截断轨迹无法回答完整时长下候选最终会怎样。已知 Robotiq 开发失败轨迹在候选下观察到成功，这只是测量分歧，不是技能改进。所有结果 `formal_result_eligible=false`。

可检查的 [重放报告](../evidence/measurement/pose_shadow_v1/report.json) 记录全部病例、源文件哈希、候选配置和执行输入。候选定义见 [测量说明](pose_measurement_candidate_v1.md)。
