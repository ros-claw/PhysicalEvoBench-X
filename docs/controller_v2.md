# 控制器 v2 的开发变更

2026-10-23 的完整请求/实际轨迹审查发现：v1 每次进入运动阶段都以**当前测量位置**重建参考轨迹起点，但该 tick 发出的仍是上一阶段参考位置。若上一阶段存在允许的跟踪误差，下一 tick 的参考就会跳变。例如 Panda 的 0.03 m/s 抬升设置，在阶段边界出现约 0.132 m/s 的请求位置差分，而实际峰值约为 0.0303 m/s。

`grasp_lift_state_v2` 改为从上一阶段**最后请求位置**接续参考。抬升终点仍固定为进入 LIFT 时实测 TCP + 0.12 m；不改变抬升目标、judge、成功阈值或初始五维参数。v2 的每段参考仍使用相同的速度/加速度规划，实际 TCP 速度受物理闭环影响，不宣称逐 tick 严格等于参考速度。

SkillSpec 显式记录 v1/v2；初始开发技能改用 v2。v1 执行器分支保留用于审计旧记录。提案器不能更换 controller family。历史结果仍属于其原始代码版本，增加的实测 TCP/关节越界检查也记录为本次代码修订；不得将历史 v1 结果重新标为 v2 验收。

旧参数范围不立即删除。新的共同范围先在独立开发配置 `configs/development/common_range_candidate.yaml` 提案，双本体做每维低中高 15 回合和 8 个预先声明的组合边界压力条件；在结果审查前不改变正式范围或启动正式 pilot。即使所有测点通过，也只是有限开发覆盖，不能证明连续五维空间处处成功。

共同范围候选保留原始初值 `(0.50, 0.07, 0.30, 0.10, 0.30)`。提出收窄的依据是机械到位失败和高速度跟踪饱和，不依据任何正式测试结果或方法排名。全部旧失败点和长等待时的稳定性失败保留。

原 Robotiq 0.80 s 等待失败的 HOLD 轨迹中，345 个采样有 41 个角速度超过固定 0.5 rad/s，最高约 0.776 rad/s；最长合格保持约 0.48 s。此测量解释为何 judge 未给成功，不证明角振动的完整接触因果机制。低抓取高度的机械干涉仍仅是与轨迹一致的假设，尚无接触力证据。
